# نظام التنمية المحلية

تطبيق مكتبي عربي لإدخال البيانات ومراجعتها وتحليل أولويات التنمية محليًا، مع قاعدة SQLite مشفّرة (SQLCipher). لا يرسل التطبيق ملفاتك ولا قيمك إلى أي خدمة خارجية؛ التعرف الضوئي يعمل محليًا داخل الجهاز.

الإصدار: 0.4.0

## أول تشغيل

- لا توجد كلمة مرور. يولّد التطبيق مفتاح تشفير عشوائيًا (256 بت) مرة واحدة ويحفظه في `store.key` بجوار قاعدة البيانات.
- إذا وُجدت قاعدة بيانات وفُقد `store.key`، يرفض التطبيق العمل ويطلب استعادة المفتاح من مجلد `backups`. لا يولّد مفتاحًا جديدًا كي لا يجعل بياناتك غير قابلة للقراءة.
- إذا كان الملف الموجود ليس قاعدة يخص التطبيق (مفتاح مختلف)، تُنقل نسخة بايت-ببايت إلى `backups` قبل أي إجراء، ثم تُحجر القاعدة القديمة ويُبدأ متجر جديد.
- زر النسخ الاحتياطي في الشريط العلوي ينشئ نسخة في `backups` (يُحتفظ بأحدث 10).

## سير العمل

1. **استيراد**: Excel `.xlsx` أو PDF أو Word `.docx`. كل قيمة مستخرجة تبقى مسودة للمراجعة، ولكل قيمة ملف مصدرها وموضعها.
2. **مراجعة الاستخراج**: أكمل المفتاح الجغرافي (المحافظة، المديرية، العزلة، التجمع) ثم اعتمد. الحفظ يخبرك صراحة بما حدث: حفظ، أو رفض بسبب حالة السجل، أو تحديث القيمة المعتمدة المرتبطة.
3. **ترحيل إلى التحليل**: زر واحد يحوّل القيم المعتمدة إلى مديريات في شاشة التحليل، ويربط كل قيمة بسجلها في `data_values` (عمود `data_value_id`) حتى تبقى قابلة للتتبع.
4. **تحليل الأولويات**: مساران (مطابقة القالب / المعايرة العلمية)، فجوات بيانات، حساسية، محرر أوزان، بطاقة قرار لكل مديرية (الوحدة، القيمة الخام، المصدر، الموضع، تاريخ الالتقاط) وبطاقة فرصة تنموية مشتقة.
5. **التصدير**: Excel (ست أوراق) أو PDF. التصدير لا يعدّل قاعدة البيانات.

## الحقول الحساسة ووضع المشاركة

الschema يصنّف الحقول `public` / `restricted` / `sensitive`. زر الوضع في الشريط العلوي يبدّل بين:

- **مالك الجهاز**: كل الحقول ظاهرة.
- **وضع المشاركة**: الحقول المقيّدة والحساسة تُحجب في القراءة والتصدير، وكل قراءة محجوبة تُسجَّل. لا يمسح حفظ النموذج في هذا الوضع القيم المحجوبة، لأن الحقول المحجوبة تُستثنى من الكتابة أصلًا بدل إرسال فراغ.

## سجل التدقيق

- `access_log`: كل كتابة وتصدير وترحيل وتعديل أوزان.
- `audit_reads`: كل قناة قرأت بيانات — الكيان، الحقول المحجوبة، عدد الصفوف، الجلسة. تبويب «سجل التدقيق» يعرض الجدولين.
- `directorate_versions`: لقطة كاملة (السجل + مصادره) قبل كل تعديل أو حذف، مع استعادة ممكنة. يُحتفظ بأحدث 20 لقطة لكل مديرية.

## OCR

- يعمل محليًا بـTesseract العربي (نموذج `4.0.0_best_int`) مع معالجة مسبقة: رمادي، شد تباين بنسب مئوية، تصحيح ميل، تكبير إلى 300DPI، تدوير تلقائي عند فشل القراءة.
- كل حقل مقترح يحمل ثقة القراءة ودرجة تطابق الاسم. الحقل المشكوك فيه لا يُحدَّد تلقائيًا، ولا يُطبَّق إلا بتعليم صريح. لا يوجد مسار قبول تلقائي.
- القيمة التي لا يمكن تحليلها لا تُقترح أصلًا؛ تُعرض كسطر يحتاج إدخالًا يدويًا.
- المسودة تُحفظ في `ocr_drafts` و`ocr_field_confidence` مع قرار لكل حقل؛ القراءة قابلة للإلغاء من الشاشة.
- الحد المستخدم 40 ميغابايت للملف، و100 صفحة PDF لكل قراءة، و120 ثانية لكل صفحة.

## حدود معروفة

- الدقة الخام على نموذج قياس مولّد 12/14 (85.7%)، والزمن 3–5 ثوانٍ للصفحة. لا توجد بعد مجموعة صور ميدانية حقيقية للقياس عليها؛ انظر `تدقيق-شامل/قياس-OCR/v2/ملخص-قياس-OCR-v2.md`.
- زمن التحليل ينمو خطيًا: 5,000 صف ≈ 0.8s للإدراج و0.4s للتحليل، و20,000 صف ≈ 3.1s و1.7s. الحمولة عبر IPC تُقلَّم الآن (تُقرأ تفاصيل الصف عند الطلب).
- لا يدعم XLS أو DOC القديم. الجداول متعددة الصفحات والمسوحات الرديئة تحتاج تصحيحًا يدويًا.

## التطوير والاختبار

يلزم Node.js 22 أو أحدث. ثبّت الحزم من ملف القفل باستخدام `npm ci`، ثم:

- `npm run dev:desktop` لتشغيل التطبيق في بيئة التطوير.
- `npm test` لاختبارات قاعدة البيانات المشفّرة، المراجعة، الاستخراج، المخطط، الجسر، السياسة الأمنية وOCR.
- `npx electron scripts/e2e-analysis.cjs` لاختبار شامل على التطبيق الحقيقي (41 فحصًا) مع أدلة في `تدقيق-شامل`.
- `npm run build` لبناء واجهة الإنتاج.
- `npm run dist:win` / `dist:win:zip` / `dist:win:dir` لبناء Windows x64.

الحزم غير موقعة رقميًا، لذلك قد يعرض Windows تحذير SmartScreen. قاعدة البيانات في مجلد بيانات المستخدم باسم `development-data.db`، والمفتاح في `store.key` بجوارها.
