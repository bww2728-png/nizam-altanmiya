# مرجع RAGFlow للتكامل

يرتبط مصدر RAGFlow الرسمي داخل هذا المستودع كـ Git submodule، مثبتًا على `v1.0.0` والـ commit `db1cd5929a7885a3074547791f5ecc4d2f891739`. هذا يثبت المصدر ضمن إصدار المنتج دون نسخ تاريخ upstream أو تعديل ملفاته.

عند استنساخ المشروع، استخدم `git clone --recurse-submodules`، أو نفّذ `git submodule update --init --recursive` داخل نسخة موجودة. في صفحة GitHub يظهر `vendor/ragflow` كرابط submodule إلى المصدر المثبت؛ لا تُنسخ ملفات RAGFlow إلى المستودع الرئيسي.

ملف `deployment-manifest.json` يحدد المرجع والخدمات والبوابات المفتوحة. للتحقق محليًا من الوسم والـ commit وملفات Compose:

```sh
node tools/validate-ragflow-reference.cjs
```

الفاحص لا يشغّل Docker ولا يثبت أي خدمة. التكوين الحالي مرجع upstream فقط، وليس Compose خاصًا بالمنتج أو إعدادًا صالحًا للإطلاق. لا تشغّل إعدادات upstream كما هي؛ يلزم إنشاء طبقة نشر للمنتج بعد تدقيق المنافذ والأسرار والصور والتراخيص.

## ما لم يُختبر أو يُحسم

- لا تتوفر هنا بيئة Windows أو WSL2 أو Docker؛ لم يُختبر تثبيت أو بدء تشغيل أو إيقاف أو استعادة على جهاز Windows.
- اختيار WSL2 مقابل VM غير محسوم ويحتاج اختبار دورة حياة على جهاز Windows x64 مستهدف.
- ملف Compose يذكر الخدمات والصور، لكنه لا يثبت بصمات الصور ولا حقوق إعادة توزيعها، ولا يشكل حزمة Offline.
- خدمة TEI اختيارية وغير مفعلة افتراضيًا في upstream؛ نموذج Embedding لم يُختَر ولم توضع أوزانه محليًا. يجب قياس الذاكرة والأداء واختبار retrieval عربي مرخص قبل الاختيار.
- لا يوجد بعد Compose overlay خاص بالمنتج، أو Runtime Manager، أو installer موحد، أو SBOM، أو أصول Offline موثقة البصمات.
