# معالجة الوثائق والبحث المحلي: التصميم والحالة التشغيلية

## القرار المعماري

تبقى قاعدة SQLite المحلية غير المشفّرة هي المصدر الرسمي للسجلات المعتمدة. يحتفظ سجل الوثائق بالملف الأصلي وبصمة SHA-256، وتخزن نتائج الاستخراج والعناصر النصية بوصفها مخرجات مشتقة للمراجعة والبحث؛ لا يؤدي استخراجها أو فهرستها إلى اعتماد بيانات أو تغيير مؤشرات التنمية. يبقى ExcelJS ومسار Excel الحاليان دون استبدال.

## تدفق التنفيذ الحالي

1. يختار المستخدم ملفًا من نافذة النظام. يحدد التطبيق نوعًا مسموحًا بالامتداد والتوقيع، ويحد حجم الملف إلى 50 MiB. ملفات DOCX تمر بفحوص ZIP إضافية لأسماء المسارات وأحجام المحتوى ونسبة الضغط.
2. تحفظ البايتات الأصلية وبصمة SHA-256 في قاعدة البيانات المحلية، مع منع إنشاء نسخة مطابقة بالبصمة نفسها.
3. عند اختيار «استخراج محلي ومراجعة»، ينسخ التطبيق الأصل مؤقتًا ويعالجه محليًا. PDF وDOCX يوجهان إلى Docling عند توفره، والصور إلى PaddleOCR عند تثبيت النماذج العربية محليًا؛ أما XLSX/XLSM فتقرأه ExcelJS في Electron مباشرة، لكل ورقة صفوفها مع مواضع الخلايا. لا تستخدم قيم الصيغ المحسوبة في هذا المسار، ولا تُنفّذ الصيغ.
4. تحفظ العناصر المنظمة وMarkdown ونتيجة OCR إن وجدت، مع النوع والترتيب والصفحة/الورقة والصف/الخلية والموقع والثقة ومعلومات المصدر المتاحة. تصبح الوثيقة في حالة مراجعة. لا يُقرأ OCR من صور المصنفات أو صفحات PDF الممسوحة تلقائيًا، ولا يعتمد العامل القيم في سجلات المديريات أو المؤشرات أو المشاريع.
5. بعد الاستخراج، يطابق التطبيق العناوين والمرادفات المعتمدة مع حقول النماذج المنشورة فقط، ويعرض القيم المقترحة مع القيمة الأصلية والمصدر والمقتطف ودرجة مطابقة أولية. تُوحّد الأرقام العربية والفواصل الواضحة للحقول العددية، ولا يُستنتج الصفر عند غياب قيمة؛ تبقى كل النتائج بحاجة لمراجعة. الحقول التي لا يغطيها نموذج منشور تُعلّم بأنها غير متاحة.
6. يستطيع المستخدم مراجعة كل مرشح ورفضه أو تأكيده مع مبرر، ثم إنشاء سجل مستقل لكل صف Excel أو صفحة PDF أو وثيقة إذا اختارها. يتحقق الخادم من ارتباط الحقول بنموذج منشور ومن أن كل سجل يجمع أدلة موضع مصدر واحد؛ ويحفظ العملية دفعة واحدة أو يتراجع عنها كاملة عند الخطأ. تُحفظ القيم ومقتطفاتها ومواضعها وبصمة الملف في سجل الأثر. لا يستبدل ذلك سجلاً قائمًا، ولا يصبح أي سجل معتمدًا أو يدخل التحليل الرسمي قبل إتمام اعتماده وفق مسار التطبيق.
7. البحث النصي المحلي يطابق النص المستخرج حرفيًا بعد تطبيع بعض الاختلافات العربية، ولا يدعي أنه بحث دلالي.
8. يمكن للمستخدم، بعد تهيئة خدمة خارج عملية Electron على `127.0.0.1:9380`، رفع الملف الأصلي إلى مجموعة RAGFlow، طلب استرجاع مقاطع، وإظهار المقتطفات التي أعادتها الخدمة. لا يستدعي التطبيق endpoint لتوليد إجابة. يحتفظ التطبيق بمرجع المجموعة والوثيقة والحالة محليًا، ويمكن فحص الحالة يدويًا من شاشة مراجعة الوثيقة.

## إعداد وتشغيل محلي — غير مجهز كتثبيت إنتاجي

- يلزم Python مستقل مثبت ومدعوم وإعداد بيئة مقفلة الاعتمادات. العامل يتوقع أن يكون `python3` في Linux/macOS أو `python` في Windows، ويمكن تحديد المسار بواسطة `DOCUMENT_WORKER_PYTHON`.
- يتطلب OCR للصورة مساري نموذج محليين صالحين في `PADDLEOCR_DETECTION_MODEL_DIR` و`PADDLEOCR_RECOGNITION_MODEL_DIR`. يمنع غيابهما الادعاء بأن OCR جاهز. لم يضف المستودع تنزيلًا أو تجهيزًا لهذه النماذج.
- `HF_HUB_OFFLINE` و`TRANSFORMERS_OFFLINE` مضبوطتان على وضع offline، ويمنع العامل اتصالات `socket` المعتادة. هذه قيود داخل العملية وليست حاجز شبكة نظاميًا؛ يلزم جدار ناري واختبار خروج شبكي على الجهاز المستهدف لفرض منع الخروج.
- يتطلب البحث وجود خدمة RAGFlow أُعدت وشُغلت خارجيًا على المنفذ المحلي المحدد ومجموعة معرفة ومفتاح API. يحفظ التطبيق المفتاح عبر `safeStorage`. لا يجهز المشروع Docker أو قاعدة RAGFlow أو نموذج embedding أو بيانات نموذج.
- يجب ضبط RAGFlow نفسه كي لا يرسل الملفات أو النصوص أو الاستعلامات إلى مزودات بعيدة، وربطه بواجهة loopback فقط. سياسة التطبيق تقيد واجهات Electron الشبكية إلى عناوين GitHub الرسمية للتحديثات ونقاط RAGFlow المحددة محليًا؛ لكنها لا تضبط شبكة Docker أو البرامج الأخرى.

لذلك فإن تسليم هذا الفرع لا يعني أن خدمات Docling أو OCR أو Polars أو RAGFlow تعمل تلقائيًا على جهاز المستخدم، ولا أن النظام بأكمله اجتاز اختبار العمل دون إنترنت.

## حدود الأمان والتوافق

- DOCX وPDF والصور وXLSX/XLSM تمر بفحوص أولية، لكن محللات المستندات الخارجية لم تُشغل هنا على عينات حكومية عربية أو ملفات عدائية. العامل subprocess وليس sandbox بنظام التشغيل؛ لا يفرض حد ذاكرة أو CPU من النظام، وحده الزمني في التطبيق دقيقتان.
- صور المصنفات لا تُرسل تلقائيًا إلى OCR، وملفات PDF المصورة لا تمر حاليًا بمسار تحويل صفحات إلى صور ثم PaddleOCR. لذلك لا يوجد دعم مثبت لـ OCR على PDF الممسوح.
- لا يوجد اختبار جودة عربي يحسب CER/WER، ولا مجموعة Ground Truth أو معايرة لثقة OCR. الثقة المعروضة مؤشر تعرف لا دليل صحة.
- Polars لا يغير قواعد المؤشرات أو الترتيب، لكنه ليس مدمجًا في الاستيراد الحالي. ExcelJS هو المسار الخلوي الدقيق، والصيغ لا يعاد حسابها.
- لم تُختبر API الخاصة بـ RAGFlow على خدمة حية. اختبارات الوحدة تستخدم استجابات محاكية، ومسار الصحة `/api/v1/system/healthz` ما زال يحتاج تحققًا من النسخة المنشورة. قد تختلف حقول الاستجابة باختلاف إعداد الخدمة أو النسخة.
- فشل RAGFlow لا يمنع قاعدة النظام أو التحليل الأساسي، لكن البحث المعرفي والفهرسة لا يعملان دون الخدمة.
- البحث المعرفي يعيد مقاطع مصدر لا إجابات مولدة؛ لا يضمن التطبيق وحده أن المقاطع كاملة أو أن كل صفحة/مرجع أعادته الخدمة صحيح.

## التحقق المنفذ وما لم ينفذ

اختبارات الوحدة تغطي قيود عناوين RAGFlow المحلية، طرق ومسارات الشبكة المسموحة، عرض الأدلة دون توليد إجابة، طلب الرفع والفهرسة، عدم تكرار طلب الفهرسة أثناء حالة المعالجة، فحص حالة المرجع، تخزين الأصل وإزالة تكراره وتخزين نتائج المراجعة والبحث النصي. هذه الاختبارات لا تشغل محركات خارجية.

غير منفذ/غير مثبت: تشغيل Docling وPaddleOCR وPolars فعليًا، تقييم PDF/DOCX العربية، اختبارات OCR المقاسة، خدمة RAGFlow الحية، اختيار/مقارنة BGE-M3 وMultilingual E5، فلاتر metadata الحية، الفهرسة دون اتصال، Docker Compose، تثبيت مكونات Python بإصدارات مقفلة وملفات hash، SBOM، قياس الموارد على ملفات كبيرة، E2E لتدفق مركز الوثائق، واختبار تثبيت Windows.

لا يُعلن عن أي من هذه الوظائف باعتبارها مكتملة حتى تجهيز بيئة تشغيل متوافقة، إضافة fixtures عربية موثقة مع تراخيصها، وتنفيذ الاختبارات الفعلية المذكورة أعلاه.
